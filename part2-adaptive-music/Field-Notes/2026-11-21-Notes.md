# Session 1: Building the Live Score

**11/12/26 – 11/21/26 / location: Homelab**

**What I'm doing:** Getting a capture to audibly drive music in real time, then replacing the placeholder sounds with real music. Full capture runs with the final sounds come next session.

**Setup:**
- Lab laptop (Ubuntu): Suricata 8.0.3 (ET Open), `timeline.py`
- Desktop (Windows 11): FMOD Studio 2.03.15, FMOD Engine 2.03.15, `listener.py`
- Same home network, UDP 9500

## Workflow

1. Ran Suricata on each capture (`TZ=UTC`, `-k none`) and built timelines with `timeline.py`.
2. Wrote `listener.py` to replace the print-only UDP listener. It loads the FMOD banks through the FMOD Studio C API (`ctypes`), sets the score's state from each message, and plays a check-in sound on every C2 event.
3. Built the FMOD project with placeholder sounds made in Audacity, then tested with `--demo`.
4. First live run: laptop playing First-to-Last at `--speed 5`, desktop listening.
5. Reworked the FMOD event so layers fade smoothly and stay on the beat (see Decisions).
6. Searched Looperman for loops, auditioned them, processed them into five files (tempo, length, clicks, levels) and swapped them into FMOD.

Commands:

```bash
# laptop
python3 timeline.py 2026-08-09-First-to-Last --play --speed 5
```

```powershell
# desktop
python .\listener.py --demo
python .\listener.py
```

## What I heard/noticed

**First live run (placeholders, First-to-Last):** It worked from start to finish: events printed on both machines and the music followed. The music went **straight from baseline to C2**. The first strong alert was a FormBook check-in (02:13:26), and the only download alert came five minutes later (02:18:31, the second EXE). The initial infection never triggered an ET Open rule, so there was no infection stage to hear. Detection gaps become silence.

**Placeholders:** A sine wave, pink noise and a square wave proved the system worked, but sounded nothing like music. The check-in blip was accidentally 15 seconds long at first (Audacity read `0.15` as 15 s), so ten check-ins blurred into one long tone.

**Synthesized "music" v1:** Generated chords, drums and pads in a lo-fi style. Rejected. It had the same fake quality that bothered me in Part 1.

**Real loops, baseline:** The Clocks set (Rhodes, upright bass, acoustic guitar) with soft boom-bap drums. Decent, real-sounding, and in the warm jazz-hop direction. I rendered one version with horns and one without and haven't picked yet.

**Violin (infection):** I really like how it sits over both baseline versions. It darkens the groove without taking over.

**Phonk (C2, first attempt):** 808 drums plus a Memphis cowbell. It felt out of place. It's a different genre on a double-time beat and much louder, so it sounded like someone switched songs rather than the same music getting darker.

**Orchestra (C2, final):** A cello pattern, two string layers and taiko. Of the three options (dark, cinematic, full), the full one fit best. It escalates the violin's mood instead of replacing it. The baseline needed to drop a bit when it comes in, so it dips 4 dB.

**Pizzicato check-in:** A high plucked cello note on D. It's noticeable without being loud because it sits above the low, heavy C2 mix, and it's on the home note, so it never clashes.

## Decisions

- **Continuous `Level` instead of a labeled `State` parameter.** Labeled parameters are discrete, so volume automation jumped instead of fading. `Level` (0/1/2) with a Seek modulator glides between states over about 2 seconds.
- **All loops run all the time; only their volume changes.** In the first layout, each layer started when its state began, so it came in off the beat. Now everything starts together and stays in sync, which means tension and threat can have rhythm.
- **Press q to quit.** Ctrl+C didn't stop the listener on Windows, first because of the blocking socket and then because FMOD seemed to swallow it. A 20 ms socket timeout plus a keypress check fixed both.
- **Real recordings only.** Looperman loops plus one CC0 orchestral sample. No synthesized sounds.
- **D minor at 86 BPM.** My reference song is E minor at about 87, but D minor at 86 had complete loop sets (several parts from one producer), so they fit together.
- **Drums on their own track.** It was needed for the phonk swap, and it's kept so the drums can change separately later.
- **Stayed with FMOD over Pure Data** (my professor suggested Pd). FMOD is built for this kind of layered, state-driven score from recordings, and it already works. Pd would be better for detailed data-driven mapping and a Linux/open-source live version, so I may come back to it.
- **The nine facts and the mapping** are now written down in `docs/design.md`. That's the basis for measuring what survives.

## Surprises or problems

- **The FMOD Engine is a separate download from FMOD Studio.** The listener needs the Engine's DLLs.
- **FMOD keeps its own copy of imported audio** in `fmod/Assets`. Replacing files in `studio/sounds` alone changes nothing.
- **Built banks go stale.** "FMOD error 74" meant the `Level` parameter didn't exist in the built files yet; rebuilding (F7) fixed it.
- **`.cache/` holds encoded audio** of the loops. It's now ignored so the loops aren't redistributed through the repo.
- **One of the bass loops ends mid-note,** which made a click every time it looped. A 10 ms fade fixed it.
- **RMS timeline:** the 37-minute C2 session is a single event, because `timeline.py` only marks flow starts. In the music, the orchestra plays with almost nothing happening. Duration and data volume are lost before any sound is made (see `analysis/timeline-summary.md`).
